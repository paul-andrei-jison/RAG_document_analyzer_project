How It Works

Up and running in
five steps

DocuMind is fully local. No accounts, no API keys — just install the prerequisites and run.

01
Install Ollama
Download and install Ollama from ollama.com — it's the local AI engine that runs on your machine. Available for Mac, Windows, and Linux.
02
Pull an AI model
Pull any model from Ollama's library. LLaMA 3.2 is a solid default, but you can use mistral, phi3, gemma2, or any other model you prefer.
Terminal 
ollama pull llama3.2
03
Clone the repo & install dependencies
Download the source code and install all Python packages. Requires Python 3.10 or higher.
Terminal · clone 
git clone https://github.com/paul-andrei-jison/RAG_document_analyzer_project.git
Terminal · install 
cd RAG_document_analyzer_project && pip install -r requirements.txt
04
Start the server
Run the FastAPI server. Use the first command for local access only. Use the second to share with teammates on the same network — then give them your machine's local IP (e.g. 192.168.1.x:8000).
Terminal · localhost only 
uvicorn main:app --reload
Terminal · share on network 
uvicorn main:app --host 0.0.0.0 --port 8000
05
Upload docs & start chatting
Open localhost:8000 in your browser. Click the upload button to add PDFs or TXT files. Once processed, type any question — DocuMind searches across all your documents simultaneously to answer it.
Step 01 · AI Runtime
Ollama is the engine that runs your AI locally
It acts as a local server on port 11434. DocuMind connects to it to generate both document embeddings and chat responses — no internet required.
ollama.com → download installer
Run installer for your OS
✓ Ollama running on port 11434
Step 02 · AI Model
Pull any model — not just LLaMA
DocuMind works with any model Ollama supports. You can switch models in the UI dropdown without restarting the server.
ollama pull llama3.2
ollama pull mistral
ollama pull phi3
ollama pull gemma2
→ Any of these will work
Step 03 · Dependencies
Python packages the app needs
pip reads requirements.txt and installs everything — FastAPI, ChromaDB, Ollama client, PyPDF2, and uvicorn.
✓ fastapi
✓ chromadb
✓ ollama
✓ pypdf2
✓ uvicorn
Step 04 · Server
One command starts the whole app
FastAPI serves both the API and the frontend. --reload is for local dev. Use --host 0.0.0.0 to let network teammates connect by your local IP.
GET / → app UI
POST /upload → ingest doc
GET /documents → list docs
POST /chat → ask question
→ Visit localhost:8000
Step 05 · RAG Pipeline
What happens when you ask a question
Every question runs a full retrieval-augmented generation pipeline — your query becomes a vector, the closest document chunks are found, and the AI generates an answer from them.
1. Query → embedding vector
2. ChromaDB similarity search
3. Top 5 chunks retrieved
4. Context assembled as prompt
5. Ollama generates answer ✓

FAQ

Common
questions

DocuMind currently supports PDF (.pdf) and plain text (.txt) files. PDFs are parsed with PyPDF2 to extract text from each page, which is then split into chunks and embedded into ChromaDB for semantic search.
No GPU required. Ollama runs comfortably on CPU with quantized models like LLaMA 3.2. Response times will be slower without a GPU (a few seconds per reply), but it's entirely functional on most modern laptops and desktops.
Yes. Any model available through Ollama works with DocuMind. Pull a model with ollama pull <model-name>, then select it from the model dropdown in the UI. Popular options include mistral, phi3, gemma2, and qwen.
Yes. Start the server with uvicorn main:app --host 0.0.0.0 --port 8000 and share your local IP address. Anyone on the same network can access DocuMind in their browser without any additional setup.
Documents are stored locally in a ChromaDB vector database at ./local_vectordb in the project directory. The original files are deleted after ingestion — only the extracted text chunks and their embeddings are persisted. Nothing leaves your machine.
